# 三段录屏反馈核查（2026-10-20）

## 录屏事实

用户提供的三段录屏时长分别约为 54 秒、20 秒和 100 秒。本地提帧核对了主要页面、认证方式选择及最终提示，未将录屏中的服务商提示当作操作指令。

1. 个人认证：在服务商页面主动选择“实名手机号方式”，输入短信验证码后完成认证。返回商签通后，“认证方式”一栏显示英文 `face`。
2. 单据模板：销售单列表已有标准模板，但列表项不能进入预览。“添加销售单模板”首先显示操作菜单，用户在选择上传前看不到文件样例和具体版式。
3. 合同签署：进入“完成企业签署授权”，点击“下一步”后打开服务商企业“开通电子签”页面，完成经办人短信验证后提示企业已实名、当前账号不是企业超级管理员，需申请对商签通授权。

## 已确认的原因和边界

### 个人认证方式

个人实名服务将法大大回调或实名详情中的 `identMethod` 保存并返回，个人认证页直接展示该字段。原页面没有表达这是服务商的实名记录，也没有取得“本次页面操作实际使用方式”的独立证据。

录屏可以证明本次选择了手机号方式，不能仅凭录屏确定上游为何返回或保留 `face`。不能将英文简单翻译成人脸识别，也不能无服务端证据将记录强改为短信认证。修复后的展示应强调已核实的认证结果及认证渠道，原始字段保留用于排查。

### 单据模板

销售单和退货单自定义模板实际为 JSON 版式定义，使用列名称和空白行数；不是 Word、PDF、Excel 或已填写的单据。标准模板原列表没有预览交互，上传前的说明缺少可用样例。应提供标准版式预览、自定义文件说明和有效示例，并在保存前展示解析后的版式。

### 企业签署授权

个人实名、商签通本地角色、企业对商签通的资源授权、法大大企业成员身份及印章使用权分别核验。商签通本地管理员不能据此推定为法大大企业超管。

当前签署预检中，企业尚缺必要授权（包括组织数据范围 `organization`）会返回业务码 `46101`。本地具有企业管理权限的账号原来能从笼统的“下一步”进入企业授权，因此在服务商页面才发现自己的超管权限不足。录屏与此分支一致，但本轮没有读取或修改该企业的线上授权范围，不能把推断写成生产取证结论。

[法大大官方企业授权接口](https://dev.fadada.com/api-doc/CGKNKJZFM5/77KS5R59TERABQH9/5-1)明确：已认证企业由企业超管授权，或经办人申请超管授权。2026-10-20 已通过其公开 JSON 文档接口重新核对该规则。

企业授权是企业共用的准备事项。有效授权已具备时应实时核验并复用；普通签署人不应逐个申请相同的企业授权。当前代码已支持有本地签署权限的成员自动同步，以及有效成员和用印授权的复用。本次改进须明确补授权的办理者、公司共用的效果及返回原合同继续签署的路径，不能通过跳过外部授权来消除提示。

## 验收重点

- 短信完成实名后，个人页显示已认证及明确渠道，不再显示未经说明的 `face` 或声称本次使用了人脸识别。
- 点击标准销售单或退货单模板可以预览列及空白行；标准版式可直接使用。
- 自定义上传入口说明 JSON、文件来源及适用内容，提供可用样例；错误文件不保存，成功解析后先预览。
- 企业缺授权时，签署人先看到公司共用的授权说明；普通成员可重新检查，具备本地办理权限的人可明确选择以电子签超管身份办理。
- 企业授权后，两位有签署权限且已实名的同事复用同一企业授权，不再次创建企业授权链接。成员或印章确有权限缺失时仍按实际缺项处理。
- 从授权或检查返回后保留原合同，不把历史企业已认证直接当作补授权成功。

## 发布范围

本轮只修改工作区代码和测试，不发布小程序，不修改线上企业超管、成员或印章权限。线上实际改善需要发布对应变更，并以真实企业账号完成一次企业授权和两位签署同事的验收。

## 本次完成的修改与验证

- 个人认证页改为“认证渠道：电子签实名认证”，正常加载和续办失败路径均不再将原始方式码写入展示数据；后端仍保留诊断字段。
- 单据模板列表可预览；标准版式先看再选；自定义导入提供格式说明、有效 JSON 示例及发送示例文件的微信选择器，导入解析后先预览、改名、确认再保存。
- 企业签署授权默认操作改为“授权后重新检查”；有本地办理权限的人可明确选择“我是电子签超管，去授权”。补授权标题和企业认证页说明保持一致，原合同续办机制不变。
- 完整前端测试 **386 项通过**（基础 89、Node 行为 285、法人流程 12）；后端企业认证及签署成员专项 **150 项通过**。

- 静态布局和服务替身不代替微信真机及实际法大大账号验收。示例文件的选择／发送、真实企业授权、成员激活及用印权限仍需发布后验证。
