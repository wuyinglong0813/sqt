# 法人首次入驻与按需签署待办

## 发布范围

本轮合入两个仓库当前全部代码，包括仅法人首次入驻、企业主页按需签署待办、企业资料次页和已有库存备注修复。前端只提交和推送，由用户自行上传、审核和发布；后端按既有三进程发布器整体更新 identity、business、gateway。

源码中的 `tradepass.fadada.legal-representative-only-onboarding-enabled` 默认仍为 `false`。本次部署明确在 `TRADEPASS_CORE` 分组的 `tradepass-identity.yaml` 中设为 `true`，通过私有原文备份、单属性比较、CAS 发布及重启后回读确认；common、business、gateway 配置摘要单独保留和核对。

开启后仅允许已核实的法人本人完成首次入驻。员工仍可被邀请加入，既有正式企业的管理员补资源授权保持原流程。已有法大大代理人认证但缺少当前法人本人证据时继续待核验，不凭姓名、超管授权或清理本地数据自动开通法人。

## 页面与状态读取

- 企业首页移除常驻的“法人身份核验”“电子签成员”及失效链接恢复行。
- 新增“企业资料与身份信息”次页，展示当前接口可见的企业资料和本人角色；历史实际法人可从次页进入已有身份核验。
- 有签署权限的当前成员才读取本人准备状态；已就绪或无签署要求时隐藏待办。
- 缺项时显示“完成本人实名”“确认加入电子签企业”“待管理员完成用印授权”或“重新检查”。本地有管理权限的办理人可继续原官方授权页，服务商最终确认用印管理权限。
- 页面加载、重新检查、企业切换后只调用只读 `GET /api/fadada/companies/{companyId}/signing-readiness`，不创建成员、邀请或授权链接。切换企业或退出页面后忽略旧响应。
- 返回字段为 `status/message/action/canManageSealAuthorization`。服务端以当前会话的 userId 和 ACTIVE 成员关系限定查询，使用有效角色权限和本地实名/企业/准备队列；不接收目标 userId。
- 旧 `READY` 仅证明成员同步，不展示为签署完成；只有 `SIGNING_READY` 且无错误才隐藏首页待办。合同签署仍执行实时预检，首页提示不替代用印权核验。
- 用户显式确认成员已激活后唤醒后台准备；用印授权实际生效后复用既有唤醒事件。后台核验与本人必须确认的页面步骤分开处理。

## 联调兼容修复

完整隔离联调发现并修正此前遗留的验证契约漂移：新增 GET 的网关接口计数与 HTTP 基线；数据库迁移工具与当前精确 V48/owned 版本的白名单；存储故障注入的合成 OSS 凭据；支付验签回调在公共接口测试中的分类。迁移工具保持未知版本拒绝、只读源、空目标和逐行校验保护，说明见 `tools/database-migrator/README.md`，本次不执行线上迁库。

缺失或不可解析的请求体现在返回固定安全消息与 HTTP 400；支付回调验签实现保持原样，真实支付服务异常仍返回失败和 HTTP 500 以允许上游重试。
