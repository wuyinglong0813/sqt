# 2026-10-29 定向成员邀请、履约资料与 Logo

## 成员邀请

组织成员邀请改为先输入受邀手机号，再生成并通过微信分享。领取时以后端保存的、经过微信 phoneCode 核验的账号手机号匹配邀请目标；不能通过首次打开链接来占用邀请，也不能靠客户端自报手机号通过。只保存目标手机号摘要和脱敏展示值。

发起人自领、号码不符、未核验手机号、旧未指定目标的成员邀请均不能提交成员申请；这些失败不会消耗邀请码。已实名要求、管理员审核分配角色、过期和单次使用约束保留。企业合作邀请保持原流程。

手机号核验新增 `sys_user.phone_verified_at`：只有服务端微信手机号授权成功会写入；历史号码不盲目视为已核验。认证续办需同时满足手机号可信核验及个人实名。前端修改受邀号码、切换企业或登录会话后清除旧分享状态。

迁移：flat V51、identity V6。旧的通用成员邀请继续保留为历史记录，但领取时要求重新发送定向邀请；历史已填手机号的受邀账号可能需要重新通过微信核验。拆库工具版本守卫同步到 V51。

## 履约资料

- 分类筛选：全部、销售单、退货单、转款凭证、发票、物流单、其它资料；只显示当前账号有权限的分类。
- 列表减少解释文案和嵌套边框，突出名称、状态、金额、日期；“履约资料”一级标签不再重复显示数量。
- “全部”作为概览，每类只显示最近 3 条；分类标题右侧仅保留小号线条加号，“全部 N 条 ›”移到该组记录末尾。没有记录但有创建权限的分类也保留加号入口；无记录且无创建权限的分类不展示。
- 记录行仅展示内容与进入箭头。销售单、退货单详情直接展示实际 PDF 的全部页面图片，不再用结构化信息卡和商品表格替代正文；图片下方保留“查看 PDF / 下载 PDF”。发布、同意、驳回、入库、作废审批、进展、编辑、撤回和删除等业务操作统一收进右上角“更多”，仍走原签名、选仓和确认流程。发票、转款凭证及其它分类中的 PDF 附件采用相同图片阅读与底部 PDF 按钮；非 PDF 图片直接展示，Word 等其它文件仍可打开原文件。
- 去掉顶部通用新增按钮和“新建销售单”等长文字按钮；概览和分类页都在分类标题右侧使用加号，读屏标签保留完整动作名称。合同只读时关闭创建和普通修改操作；当前待处理作废的同意、拒绝和撤回保留入口，终态合同禁止修改。
- 分类列表支持单号、文件名、企业及日期搜索和状态筛选，在完整授权列表上先搜索/筛选，再按每批 20 条逐步展示；切换分类时重置展示数量并定位到列表顶部，修改查询/筛选时也重置数量。保留后端按 created_at DESC、id DESC 的顺序，不将大整数 ID 转成 JavaScript Number。
- 菜单执行前重新获取当前记录、权限和申请 ID，防止已更新/删除、权限撤销、切换合同或申请被替换后的旧菜单误操作；保留原确认弹窗及付款凭证手写签名流程。图片详情关闭后不回写，重新打开同一图片复用进行中的下载，加载时阻止菜单再次下载同一路径，避免分片并发写坏缓存。

布局在 320、375、430 像素宽度检查：分类可横向滚动，列表无页面横溢，底部操作可滚动且取消按钮可见。正式微信端仍需发布前真机验收。

最新概览、空列表、实际 PDF 单据详情及更多预览位于 `exports/pdf-reader-layout-20261029/`；原 PDF 和各页图片样例位于 `exports/pdf-page-preview-20261029/`。这些为源码渲染的布局预览，仍需在微信真机验收。

PDF 预览接口及配套后端验证见 `docs/pdf-page-preview-2026-10-29.md`；这次预览功能需要前后端配套发布，没有新增数据库迁移。

分批展示仅控制前端渲染，现有接口仍一次读取全部可见记录。若单合同增长到数千条，建议另做服务端游标分页和人员信息批量查询，不能把当前改动视为接口分页或减少传输量。

## Logo

原 512×512 PNG 有约 21px 透明边距，蓝色底又有预设圆角。新版从原矢量源导出，保留主体图形及蓝色渐变，让背景铺满正方形。

主上传文件：`exports/logo-20261029/shangqiantong-logo-upload-1024.png`。同时提供 512、240、144 PNG 备份与 SVG 源文件；不把某个尺寸作为未经核实的微信硬性要求。圆形浅/深背景预览仅供检查，不应上传该对比图。

所有上传 PNG 的 alpha 均为 255，四边无透明或白色像素；实际查看圆裁预览未裁主体。未替换小程序页面内 Logo，也未代用户上传微信后台。
