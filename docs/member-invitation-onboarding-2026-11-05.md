# 2026-11-05 成员邀请、实名与入企审核

成员邀请不再要求邀请人先输入受邀手机号。二维码、邀请码、微信分享卡片和复制的 HTTPS 邀请链接共用一个邀请记录，默认 24 小时有效，可供多位同事提交申请，管理员可以随时作废。

## 入企流程与权限

| 阶段 | 服务端状态 | 用户可以做什么 |
| --- | --- | --- |
| 登录后提交入企申请 | `PENDING_IDENTITY` | 查看本人申请的企业名称、申请进度，核验本人手机号、完成个人实名认证 |
| 手机号与实名核验完成 | `PENDING` | 查看进度、等待管理员审核；不开放申请企业的业务数据 |
| 管理员核对实名身份并分配角色 | `ACTIVE` | 仅可使用所分配角色授权的企业功能 |

已完成手机号与个人实名核验的账号申请时直接进入 `PENDING`，仍需审核。提交申请不消耗公开邀请，也不设置申请企业为当前企业；同一账号通过同码或不同码重复申请同一家企业时返回同一申请。管理员审批时在服务端重新核验申请人的手机号和个人实名，不能用管理员自己的实名结果代替申请人。

本人申请的接口只返回企业名称、申请 ID、状态及核验要求，不返回企业银行账户、合同、库存等业务信息。HTTP 企业业务入口、内部身份解析及业务权限校验共同要求有效成员和服务端确认的个人实名。待实名、待审核账号不能通过伪造企业请求头、跳过前端页面或直接调用业务接口获取权限。历史 `ACTIVE` 但未实名的账号也需先完成个人实名。

前端首页和企业页在服务端确认当前会话之前隐藏旧企业信息、指标及缓存，避免用旧的 `ACTIVE` 状态短暂展示企业数据。申请进度可在首页与企业页继续查看，个人认证页面与 SDK 返回页均通过申请 ID 续办，邀请码随后过期或被作废不会中断已经记录的申请。

## 邀请入口

- 邀请弹窗自动准备邀请码，显示有效期，提供微信分享、复制邀请码、显示小程序码、复制 HTTPS 链接及作废入口。
- 小程序码通过微信 `getwxacodeunlimit` 生成，页面为 `pages/invitation/invitation`，`scene` 只携带邀请码。扫码与分享链接最终进入同一申请流程。
- HTTPS 链接通过微信 `generate_urllink` 生成，链接有效期与服务端邀请截止时间一致。服务端邀请过期或被作废后，原二维码、卡片、邀请码、链接都不能再提交新申请。
- 小程序码与 URL Link 生成接口只允许邀请企业的管理者调用。微信接口错误会显示实际失败提示，不用普通图片或页面路径冒充可用二维码、HTTPS 链接。
- 保留此前分享弹窗按钮最多 4 个汉字的修复，以及显式重开邀请、旧响应隔离和弹窗失败反馈。

## 数据库与兼容

迁移为 flat `V52__open_member_invitations.sql`、owned identity `V7__open_member_invitations.sql`。新增 `company_invite.invitation_mode`，默认 `LEGACY`；仅新创建的无目标手机号邀请显式标记为 `OPEN`。历史无目标的旧成员邀请码不会因迁移被重新激活，原定向手机号邀请保留其核验与单次使用约束。

`company_member` 新增 `invite_id`、`invited_by`，以记录申请来源，审核列表可显示邀请人。未新增外键。拆库迁移版本守卫同步至 V52 / identity V7。

## 发布与真机验收

当前只完成本地代码与测试，未修改生产数据库、部署后端或上传发布小程序。需先应用对应数据库迁移，再发布配套后端与小程序；更新后重新生成邀请用于验收。

微信媒体接口使用实际 AppID、服务端密钥及相应接口权限。`wechat.invite-env-version` 默认 `release`，可显式配置 `trial` / `develop` 供配套测试；正式版小程序码会校验邀请承接页面已发布。真实微信小程序码、URL Link 的接口可用性、扫码唤起及实名认证 SDK 返回仍需在配套版本发布后真机验收，本地测试使用受控的微信接口响应，不代表已经在线生成成功。

真机依次检查：扫码/输码/点击分享链接、未实名申请后去认证、暂不认证退出后继续申请、实名返回待审核、审核前拒绝企业读写、管理员审核分配角色、多位账号使用同一邀请、作废邀请后禁止新申请、旧账号会话失效时不展示旧企业缓存。
