# 合同多页预览与单据模板恢复（2026-10-20）

## 合同预览

原实现从法大大图片 ZIP 中只提取最后一张签章页，小程序也只展示单张图片。因此完整 PDF 正常，但合同页面缺少正文页。

- 后端读取全部 PNG，并按文件名页码的数值排序；保留原有单页接口的最后页语义，兼容已发布的小程序。
- 新增 `GET /contracts/{id}/signed-preview-manifest`，返回 `pageCount` 和归档标识 `archiveKey`。
- 原分片接口新增可选 `page` 和 `archiveKey`；页码从 1 开始。指定页码时必须匹配当前归档标识，版本变化返回业务码 `409`，防止新旧文件混页。
- 完整归档仅下载一次，缓存有时间和总容量限制；每次请求仍执行合同参与方及内容权限核验。ZIP 的页数、单页及解压总量均有限制。
- 小程序从第 1 页开始顺序加载，标注页码；单页失败保留其他已加载页面，并支持单页或全量重试。归档变化后清空旧页、重新读取清单，清理该合同的旧图片缓存。
- 仅在清单接口明确 `404` 时兼容旧后端，且明确提示当前仅为签章页，可打开 PDF 阅读完整合同。

## 销售单、退货单模板

原“上传模板”直接打开微信聊天文件选择器，实际仅接受 JSON 模板定义文件，缺少文件格式和准备方式说明。无效 JSON 还会静默替换成标准版式。

- “添加模板”优先提供标准模板；空列表可直接恢复标准版式，无需准备文件。
- 自定义上传前说明 JSON 格式和微信聊天文件来源；无效文件明确报错。
- 删除最后一个模板时说明影响及标准模板恢复方式。已生成单据不受影响。
- 恢复标准版式通过已有模板创建接口完成，不增加后端或数据库接口；已经删除的自定义内容仍需原文件重新上传。

## 河北云域的入驻问题

用户确认此前只在法大大注册，未在商签通入驻。当前实现支持该场景，但微信登录或绑定手机号不会自动导入企业资料：先绑定当前个人实名，再由企业超管授权商签通，或由经办人在法大大页面向超管申请授权，后端核验后同步企业实名资料及印章。

当前法人身份与法大大超管身份需要分别核验；手机号只用于预填登录账号，不证明企业权限。已有法大大实名本身不阻止入驻，也不意味着此次必然完成授权。未取得河北云域的实时账号状态，未代其发起认证或更改业务数据。

本次重新读取了[法大大官方企业授权接口说明](https://cloud.fadada.com/api/edge-developer/document/nodes/CGKNKJZFM5/article?id=77KS5R59TERABQH9&version=5.1)，其已认证企业规则为超管授权或经办人申请超管授权。代码核对包含信用代码复用、旧关联冲突保护、本人实名和法人／管理员权限区分；本轮没有修改入驻逻辑。

### 同日补充：不能由现有超管配置断言法人必须找原超管批准入驻

用户截图确认云域企业已认证，法人满帅、现超管武英龙；用户说明此前由武英龙为购买服务办理注册。仅凭这些信息不能断言满帅必须取得武英龙批准才能入驻商签通，前面的口头解释对此过于绝对，现予以纠正。

- 官方企业授权说明还规定，创建集成应用的企业默认已取得应用授权并有对应企业标识；仅供该集成企业自身使用时可无需再次调用授权接口。云域是否属于商签通实际应用的创建企业仍未核实，用户也不确定。当前通用同步可按信用代码恢复已有授权，但首次入驻缺少明确识别应用所属企业、先复用默认授权的路径。
- [法大大官方企业找回说明](https://support.fadada.com/d/1704434216756932609.html)支持法定代表人本人刷脸重置超管，不必把原超管同意作为唯一处理方式。但这会让申请人成为唯一超管、移除原超管的管理权限，属于法大大账号管理变更，不能默认为商签通注册的常规步骤。本轮未发起此操作。
- 企业实名、应用资源授权、当前申请人的法人身份证明是不同核验事项。当前商签通尚未提供完整的法人自助处理衔接；既不能凭姓名自动开通法人，也不能把购服务时形成的超管身份直接当作法人入驻的必然审批人。

需要先核对实际应用归属、云域对该应用的有效授权与满帅本人身份记录，才能判断真实入驻路径和需修复的接入分支。本轮未据此修改认证或授予角色的业务逻辑。
